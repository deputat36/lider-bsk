# CRM v4 — локальный учебный сценарий

Related: #200, #205.

Mode: browser-local training only. No production data changes.

## Цель

Дать новичку возможность пройти путь:

`обращение → потребность → расчёт и КП → заказ → успешная выдача`

без создания вымышленных клиентов, заявок, КП, заказов, дизайн-задач, платежей или производственных заданий в рабочей базе.

## Учебный кейс

Локальный сценарий использует вымышленный заказ:

- учебный клиент — `Кофейня Север`;
- услуга — баннер 3000 × 1000 мм;
- материал — баннер 440 г/м²;
- макет требуется;
- монтаж не требуется;
- completeness_score учебной потребности — 85%;
- положительный финал — производство завершено и заказ выдан;
- отмена не считается выполнением.

## Хранение

Состояние тренировки хранится только в localStorage текущего браузера:

`leader_crm_v4_training_scenario_v1`

Основной quick-start использует другой ключ:

`leader_crm_v4_quick_start_v1`

Тренировка не изменяет основной quick-start и не отмечает реальные рабочие шаги выполненными.

## Browser test

1. Откройте CRM v4 и выполните `Ctrl + F5`.
2. В блоке `Первые 15 минут` найдите секцию `Безопасное обучение`.
3. Убедитесь, что показано предупреждение о локальном режиме.
4. Нажмите `Начать тренировку`.
5. Проверьте, что доступен только первый шаг `Принять обращение`.
6. Попытки перейти к следующим шагам напрямую не должны быть доступны.
7. Последовательно нажимайте `Выполнить учебный шаг`.
8. После каждого шага должны обновляться:
   - счётчик;
   - progress bar;
   - текущий шаг;
   - отметка `Выполнено локально`.
9. Обновите страницу после 2–3 шагов. Прогресс тренировки должен сохраниться.
10. Проверьте, что прогресс основного quick-start не изменился из-за тренировки.
11. Завершите все пять шагов. Должно появиться сообщение `Тренировка завершена`.
12. Нажмите `Сбросить тренировку`. Должен очиститься только ключ `leader_crm_v4_training_scenario_v1`.
13. Проверьте мобильное отображение при ширине 360–430 px.

## Network

Во время старта, прохождения, сворачивания и сброса тренировки:

- не должно быть запросов к `leader_*`;
- не должно быть запросов к Supabase REST;
- не должно быть вызовов Edge Functions;
- не должно быть никаких INSERT, UPDATE, DELETE, UPSERT, RPC или Edge Function запросов.

Допускаются только загрузка статических JS/CSS-файлов и локальная работа браузера.

## localStorage test

До начала запишите текущее значение:

`leader_crm_v4_quick_start_v1`

После полного прохождения тренировки оно должно остаться неизменным.

Ключ тренировки должен содержать только:

- `started`;
- последовательный список `completed`;
- `collapsed`.

В localStorage не должны сохраняться:

- имя реального клиента;
- телефон;
- сообщения;
- реальные ID заявок или заказов;
- суммы реальных заказов;
- токены и ключи.

## Pass criteria

- сценарий доступен после загрузки CRM;
- шаги выполняются только последовательно;
- нельзя завершить сценарий отменой;
- training progress сохраняется после reload;
- reset не затрагивает основной quick-start;
- UI не дублируется после событий `crm-ready`;
- в console нет ошибок;
- Network не содержит production writes;
- пользователь ясно видит, что данные вымышленные и локальные.

## Production boundary

Этот этап не изменяет:

- таблицы `leader_*`;
- данные production;
- RLS, policies и grants;
- Edge Functions;
- Auth;
- Storage;
- `nav_*`, `nav-*`, `parket-*` и `broker-*`.

Ручная browser/Network проверка обязательна до признания UX полностью подтверждённым.
