# Staging acceptance «заказ → производство» — 2026-07-31

## Фактический результат

В staging Supabase `otulfnouybahfnsycxqn` выполнен транзакционный сценарий:

`заказ → согласованный дизайн → производственное задание → событие`.

Runtime result:

`order-to-production acceptance: OK; cleanup verified: zero residue`.

## Что реализовано

Добавлена атомарная команда:

`production_job.create_from_order`.

RPC:

`public.leader_create_production_job_from_order_rpc(jsonb)`.

Команда:

- проверяет активного пользователя через canonical `production.write`;
- сверяет `expected_updated_at` заказа;
- запрещает архивные, закрытые и отменённые заказы;
- требует подтверждённое согласование макета;
- не считает строку `На согласовании` завершённым согласованием;
- при наличии дизайн-задачи проверяет её связь с заказом и согласование;
- создаёт одно производственное задание;
- создаёт одно производственное событие;
- обновляет производственный этап заказа;
- связывает дизайн-задачу с созданным заданием;
- сохраняет command receipt;
- возвращает существующее задание при идентичном повторе;
- возвращает `conflict` при изменённом payload с тем же idempotency key;
- блокирует второе активное производственное задание для того же заказа.

## Исправленный дефект

Первая runtime-проверка обнаружила, что простая проверка подстроки могла принять
статус `На согласовании` за согласованный макет.

Добавлен строгий helper `leader_private.leader_layout_is_approved(text)`, который:

- разрешает согласованный, утверждённый или не требующийся макет;
- запрещает `На согласовании`, `Согласование`, правки, ожидание, отсутствие готовности
  и непроверенный макет.

Повторный acceptance после исправления прошёл.
