## Обнаруженные и исправленные дефекты

### Неполный staging-контракт

До runtime-проверки `public.leader_leads` содержала только шесть технических колонок. Реальная карточка CRM v4 читает полный набор полей и не могла загрузиться, хотя изолированные транспортные тесты проходили.

Staging-таблица приведена к совместимому контракту из 33 колонок. Реальные данные из production не копировались.

### Отсутствующий authenticated read-контракт

На staging не было минимального SELECT-доступа для активного сотрудника к собственному профилю, заявке и истории заявки.

Добавлены staging-only grants и RLS-политики:

- `leader_staging_profiles_select_self`;
- `leader_staging_leads_select_active_staff`;
- `leader_staging_lead_events_select_active_staff`.

### Недостаточные права service role

Первая полноценная браузерная команда дошла до Edge, но RPC вернул HTTP 500: service role не могла выполнить внутренние helper-функции `leader_lead_workflow_error`, `leader_lead_status_requires_assignee` и `leader_lead_status_requires_future_contact`.

Для этих helper-функций выдан `EXECUTE` только роли `service_role`. Для `anon` и `authenticated` доступ остаётся запрещённым.

### Очистка приватных квитанций

Command receipts находятся в закрытой схеме и не должны удаляться браузером. Добавлена service-role-only RPC `leader_staging_lead_ui_smoke_cleanup_rpc(text)`. Выполнение отозвано у `public`, `anon` и `authenticated`.

## Советники Supabase

После DDL-изменений проверены security и performance advisors.

Критических предупреждений по выполненному lead workflow нет. Остались информационные замечания:

- RLS включён без пользовательских политик на нескольких закрытых service-only staging-таблицах;
- несколько staging-индексов ещё не использовались.

Их не удаляли и не ослабляли: это не мешает проверенному маршруту заявки и не оправдывает рискованных изменений без отдельного анализа использования.

## Граница результата

Проверен staging-маршрут:

`карточка заявки → JWT → Edge → RBAC → workflow RPC → заявка + событие → перечитывание карточки`.

Production остаётся на прежней конфигурации. Перенос серверного workflow и новых прав в production является отдельным этапом и требует отдельного подтверждения.
