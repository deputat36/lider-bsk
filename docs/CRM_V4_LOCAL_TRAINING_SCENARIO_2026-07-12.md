# CRM v4: локальные ролевые учебные маршруты — 2026-07-12

Связано с #200, #202 и #205.

## Назначение

Кнопка «Пройти учебный заказ» запускает локальный тренажёр внутри CRM. Сценарий помогает сотруднику освоить только те рабочие этапы, которые соответствуют его роли и реально доступным вкладкам интерфейса, без создания фиктивных клиентов и заказов в production.

## Полностью локальный режим

- состояние хранится в `localStorage` под единственным ключом `leader_crm_v4_training_scenario_v1`;
- schema version состояния повышена до `2`, но ключ сохранён для совместимости;
- модуль не подключает Supabase client;
- не выполняются `fetch`, REST, RPC, insert, update, upsert или delete;
- учебный заказ №`УЧЕБНЫЙ-001` не появляется в `leader_*`;
- закрытие или обновление страницы не влияет на реальные заявки, задачи и заказы.

## Как выбирается маршрут

Подсказки учитывают реально доступные вкладки текущей роли.

Тренажёр использует существующие source-only контракты `role-tab-permissions-v1.js` и `action-permissions-v1.js`, а затем пересекает разрешения роли с реально видимыми и активными кнопками `[data-v4-tab-button]`.

- `owner`, `admin`, `manager` по умолчанию получают маршрут менеджера;
- при наличии реально доступной вкладки `Производство` и соответствующего production kind можно переключиться на маршрут производства или монтажа;
- `designer` и `contractor` получают маршрут производства;
- `installer` получает маршрут монтажа;
- скрытая, disabled или `aria-hidden` вкладка не считается доступной;
- кнопка перехода в рабочий раздел не открывает недоступную вкладку и отправляет локальное событие `leader-v4:tab-denied` с причиной `training_role_not_allowed`;
- это только UI-обучение: server-side enforcement по-прежнему approval-gated в #202 и #204.

## Маршрут менеджера — 5 этапов

1. Назначить следующий контакт по учебной заявке.
2. Проверить полноту потребности.
3. Проверить расчёт и КП.
4. Создать учебный заказ.
5. Последовательно пройти производство:
   `Не передано → В производстве → Готово → Выдано`.

Попытка перейти напрямую `Не передано → Выдано` должна показать ошибку registry и не менять статус.

## Маршрут производства — 3 этапа

1. Проверить макет, размеры, материалы, срок и контрольное фото.
2. Запустить производство переходом `Не передано → В производстве`.
3. Довести учебную задачу по canonical цепочке:
   `В производстве → Готово → Выдано`.

Прямой переход `Не передано → Выдано` должен быть отклонён.

## Маршрут монтажа — 3 этапа

1. Проверить адрес, дату, инструмент, крепёж и фотофиксацию.
2. Подтвердить выезд переходом `Не назначен → Запланирован`.
3. Завершить работу по canonical цепочке `Не назначен → Запланирован → В работе → Выполнен` (после назначения маршрут продолжается со статуса `Запланирован`).

Прямой переход `Не назначен → Выполнен` должен быть отклонён.

## Manual browser verification

Test URL:

`https://deputat36.github.io/lider-bsk/crm/v4/`

### Общая проверка

1. Выполнить жёсткое обновление `Ctrl + F5`.
2. Войти под проверяемой ролью и дождаться полной загрузки CRM.
3. Нажать «Пройти учебный заказ».
4. Проверить зелёное сообщение безопасного режима.
5. Убедиться, что в заголовке и списке этапов показан маршрут текущей роли.
6. Проверить, что переключатели маршрутов отображаются только для реально доступных вариантов.
7. На каждом этапе проверить блок «Рабочий раздел»:
   - доступная вкладка получает кнопку открытия;
   - недоступная вкладка получает текстовое предупреждение и не открывается.
8. Проверить сохранение прогресса после закрытия модального окна и обновления страницы.
9. Проверить сброс маршрута и повторное прохождение.
10. Проверить закрытие по `Escape` и клику по затемнению.
11. Проверить ширины 1280, 768 и 390 px.

### Менеджер

1. Проверить прогресс `0 из 5`.
2. Пройти заявку, потребность, КП и создание заказа.
3. На статусе `Не передано` нажать «Попробовать сразу “Выдано”».
4. Убедиться, что статус не изменился, а показана ошибка запрещённого перехода.
5. Выполнить переходы `В производстве`, `Готово`, `Выдано`.
6. Проверить итог `5 из 5`.

### Производство

1. Проверить прогресс `0 из 3` и отсутствие клиентских/финансовых действий.
2. Подтвердить проверку производственного задания.
3. Проверить блокировку прямого перехода в `Выдано`.
4. Выполнить `В производстве → Готово → Выдано`.
5. Проверить итог `3 из 3`.

### Монтаж

1. Проверить прогресс `0 из 3`.
2. Подтвердить проверку монтажного задания.
3. Проверить блокировку прямого перехода в `Выполнен`.
4. Выполнить `Запланирован → В работе → Выполнен`.
5. Проверить итог `3 из 3`.

### Смена роли в одном браузере

1. Начать маршрут менеджера и закрыть тренажёр.
2. Выйти и войти под ролью `installer` или использовать отдельного тестового пользователя.
3. Открыть тренажёр.
4. Убедиться, что несовместимый сохранённый маршрут не продолжается: выбирается доступный маршрут монтажа.
5. Повторить для `designer`/`contractor`: должен открыться маршрут производства.

## Manual Network checklist

1. Открыть DevTools → Network и включить `Preserve log`.
2. После полной загрузки CRM очистить журнал.
3. Установить фильтры `Fetch/XHR`, затем по очереди проверить `rest/v1`, `functions/v1`, `leader_`.
4. Открыть тренажёр и выполнить локальные действия, не нажимая кнопку открытия рабочей вкладки.
5. Ожидаемый результат: тренажёр не создаёт новых Network-запросов.
6. Проверить manager, production и installation маршруты, включая запрещённые переходы и сброс.
7. В DevTools → Application → Local Storage проверить, что меняется только `leader_crm_v4_training_scenario_v1`.
8. Нажать «Открыть доступную вкладку». Допустимы обычные read-only запросы существующего CRM-модуля после открытия вкладки, но не запрос от учебного действия.
9. Убедиться, что отсутствуют новые `POST`, `PATCH`, `DELETE`, `UPSERT`, RPC или Edge Function вызовы, инициированные тренажёром.
10. После проверки убедиться, что в списках CRM не появились `УЧЕБНЫЙ-001` и «Учебная кофейня “Север”».

## Production boundary

- Supabase DDL/DML, migrations, RLS, grants, Auth, Storage и Edge Functions не меняются.
- Реальные записи не создаются, не обновляются и не удаляются.
- Тренажёр не должен появляться в списках CRM, аналитике или аудите production.
- Матрица ролей и server-side permissions не изменяются этим этапом.
- `nav_*`, `nav-*`, `parket-*` и `broker-*` не затрагиваются.
