# CRM startup load resilience v1

Дата: 24.07.2026

## Найденная причина зависания

После авторизации owner/admin CRM открывает управленческий дашборд. Он одновременно запрашивает семь источников:

- заявки;
- потребности;
- расчёты;
- заказы;
- производство;
- монтаж;
- коммерческие предложения.

До изменения запросы не имели предельного времени ожидания. Один зависший источник удерживал весь экран в состоянии «Загружаю рабочий стол...».

Одновременно модуль списка заявок независимо запускал восьмой запрос на событии `leader-v4:crm-ready`, даже если активным был дашборд и список был скрыт.

## Исправление

### Дашборд

Каждый источник обёрнут в существующий `timeout()` с пределом 12 секунд.

Если один источник недоступен:

- остальные данные продолжают использоваться;
- дашборд выходит из состояния загрузки;
- интерфейс показывает частичный результат;
- недоступный источник перечисляется в предупреждении;
- повторная загрузка остаётся доступна кнопкой «Обновить».

Максимальное ожидание группы параллельных запросов ограничено самым медленным таймаутом, а не бесконечным ожиданием.

### Список заявок

Список больше не загружается автоматически только из-за завершения авторизации.

Он загружается, когда вкладка `leads` действительно открыта. Если данные уже загружены, повторное открытие вкладки использует текущее состояние. Явная кнопка «Обновить заявки» по-прежнему выполняет принудительную загрузку.

Это убирает конкуренцию скрытого списка с первым рабочим экраном owner/admin и не меняет стартовый сценарий manager, для которого вкладка заявок является первой разрешённой.

## Безопасность изменения

- база данных не менялась;
- Supabase production и staging не менялись;
- бизнес-правила заявок и заказов не менялись;
- маршруты карточек не менялись;
- ручное обновление сохранено;
- частичная загрузка не маскируется как полная: предупреждение остаётся видимым.

## Проверки

Изменение применено exact-match patch-скриптом. Скрипт завершает работу ошибкой, если ожидаемый исходный фрагмент отсутствует или встречается более одного раза.

CI проверяет:

- синтаксис обоих JavaScript-модулей;
- наличие таймаута каждого источника дашборда;
- сохранение частичного режима;
- отсутствие старой безусловной загрузки списка на `crm-ready`;
- загрузку списка по `leader-v4:tab-opened`;
- сохранение принудительного ручного обновления.
