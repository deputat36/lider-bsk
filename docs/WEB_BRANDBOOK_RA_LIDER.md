# Брендбук публичного сайта РА «Лидер»

Версия: 1.0  
Статус: нормативная спецификация публичного сайта.  
Родительский документ: `docs/BRAND_SYSTEM_RA_LIDER.md`.  
Область применения: главная страница, каталог услуг, посадочные страницы, цены, примеры задач и работ, статьи, контакты, формы заявок и все будущие публичные страницы сайта.

## 1. Роль сайта

Сайт РА «Лидер» — не витрина декоративного дизайна и не каталог ради каталога. Его задача — быстро объяснить клиенту:

1. чем агентство может помочь;
2. почему ему можно доверять;
3. как выглядит реальный результат;
4. сколько примерно стоит решение или как формируется цена;
5. что нужно сделать дальше, чтобы получить расчёт или оформить заказ.

Сайт должен выглядеть как цифровое продолжение реального рекламного агентства: профессионально, современно, конкретно и без ощущения шаблонного digital-стартапа.

## 2. Иерархия целей

Приоритет интерфейса:

1. понять услугу;
2. увидеть доказательства;
3. получить ориентир по стоимости и срокам;
4. выбрать следующий шаг;
5. оставить заявку без лишних полей.

Красота обслуживает эти цели, а не конкурирует с ними.

## 3. Визуальный характер

Публичный сайт использует наиболее выразительную версию фирменной системы РА «Лидер».

Характер:

- графитовая архитектура;
- белые и светло-серые поверхности;
- фирменный orange `#FF6A00` как действие и акцент;
- крупная уверенная типографика;
- реальные работы как главный визуальный контент;
- ясная модульная композиция;
- аккуратная восходящая диагональная геометрия из логотипа.

Не использовать как системный приём:

- жёлтую фирменную палитру;
- синие digital-градиенты;
- neon/cyberpunk;
- стеклянные панели ради эффекта;
- тяжёлый glow;
- постоянные pill-кнопки;
- radius 24–36 px на всех элементах;
- emoji вместо системных иконок;
- массовый uppercase + `font-weight: 900`;
- фальшивые AI-фотографии «выполненных работ».

## 4. Источники design tokens

Главный источник digital-значений:

`assets/brand/leader-tokens.css`

Переносимая версия:

`assets/brand/leader-tokens.json`

Базовые значения:

- Brand Orange — `#FF6A00`;
- Orange Hover — `#E85F00`;
- Orange Dark — `#C84F00`;
- Orange Soft — `#FFF3E8`;
- Deep Graphite — `#0D0F12`;
- Graphite — `#171717`;
- Graphite 800 — `#242424`;
- Secondary Text — `#667085`;
- Border — `#E5E7EB`;
- Page — `#F7F7F8`;
- Surface — `#FFFFFF`.

Новые публичные страницы не должны создавать собственную альтернативную brand palette.

## 5. Цветовая дисциплина

Ориентир распределения цвета на типовой странице:

- 65–75% — white / neutral;
- 15–25% — graphite;
- до 10% — orange.

Orange используется для:

- primary CTA;
- активного состояния;
- цены или ключевой цифры;
- короткого маркера;
- части фирменного мотива;
- hover/focus;
- редкого усиленного промоблока.

Orange не используется одновременно как фон большинства карточек, всех заголовков, всех рамок и всех иконок.

Красный, зелёный и жёлтый применяются только там, где несут семантический смысл.

## 6. Логотип на сайте

Основной файл:

`assets/brand/logo-lider-header.svg`

Для компактных мест допускается:

`assets/brand/logo-lider-mark.svg`

На светлом фоне используется основной horizontal master.

На тёмном фоне полный логотип до появления отдельно подтверждённого vector dark-lockup размещается на светлой защитной плашке. Автоматически перекрашивать фирменное начертание нельзя.

Действующий размерный контракт шапки сайта сохраняется, пока отдельный PR не изменит его с визуальной проверкой:

- desktop — около 250×66;
- intermediate — около 225×60;
- mobile — около 184×49.

Логотип не должен конкурировать с H1 и CTA.

## 7. Типографика сайта

Основная гарнитура новых интерфейсов:

`Manrope, Arial, Helvetica, sans-serif`

Целевая шкала:

- Hero/H1 — 56–64 px desktop, 38–46 px mobile, weight 800;
- H2 — 40–48 px desktop, 30–36 px mobile, weight 800;
- H3 — 26–30 px, weight 700;
- H4 — 20–22 px, weight 700;
- Lead — 18–20 px, weight 500;
- Body — 16–17 px, weight 400–500;
- Small — 14 px;
- Caption — 12–13 px;
- Button — 15–16 px, weight 700;
- Price/key number — 32–40 px, weight 800.

Правила:

- заголовки преимущественно sentence case;
- uppercase — только редкий label/kicker;
- `900` не использовать как базовый вес страницы;
- line-height должен обеспечивать быстрое чтение;
- длинные текстовые строки ограничивать примерно 65–75 символами.

## 8. Контейнер и сетка

Основной desktop container — `1180px`.

Сетка:

- desktop — 12 колонок;
- tablet — 8;
- mobile — 4.

Горизонтальные поля не должны исчезать на узких экранах.

Spacing строится только из общей шкалы: 4, 8, 12, 16, 24, 32, 48, 64, 96.

Типовой вертикальный ритм:

- между элементами внутри компонента — 8–16 px;
- внутри карточки — 20–28 px;
- между логическими группами — 32–48 px;
- между большими секциями — 64–96 px.

## 9. Радиусы и поверхности

Радиусы:

- small — 8 px;
- control/button — 12 px;
- card — 16 px;
- крупный hero/CTA container — максимум 24 px.

Pill `999px` допускается только для:

- статусов;
- тегов;
- маленьких category labels;
- счётчиков.

Обычная кнопка не должна быть pill по умолчанию.

## 10. Шапка и навигация

Header должен решать четыре задачи:

1. показать бренд;
2. дать доступ к главным разделам;
3. показать телефон/контакт;
4. дать один понятный CTA.

Навигация должна быть короткой. Не превращать header в полный каталог услуг.

Рекомендуемая структура:

- Услуги;
- Цены;
- Примеры / Работы;
- О компании или Как работаем;
- Контакты;
- CTA «Рассчитать заказ».

На мобильном menu button использует системную line-icon, имеет `aria-label` и touch target не менее 44×44 px.

## 11. Hero

Hero — главный ответ на вопрос «куда я попал и что мне здесь предлагают».

Обязательные элементы:

- ясный H1 без рекламной воды;
- 1 короткий supporting paragraph;
- primary CTA;
- optional secondary CTA;
- 1–3 доказательства или факта;
- по возможности реальная работа/продукт/объект.

Допустимый dark hero:

- `#0D0F12` / `#171717`;
- один orange-мотив;
- белый H1;
- primary orange CTA.

Не использовать одновременно несколько фоновых градиентов, glow, большой паттерн, floating badges и сложную анимацию.

## 12. CTA и кнопки

Основная иерархия:

- Primary — orange;
- Secondary — graphite;
- Outline — white/neutral;
- Ghost — текстовое действие;
- Icon button — только для понятного компактного действия.

Primary CTA:

- один визуально главный CTA на viewport/смысловом блоке;
- flat orange;
- white text;
- radius 12 px;
- вес текста 700;
- состояние hover `#E85F00`;
- обязательный `focus-visible`.

Тексты кнопок должны быть конкретными:

- Рассчитать заказ;
- Получить расчёт;
- Обсудить задачу;
- Посмотреть работы;
- Выбрать формат;
- Оставить заявку.

Не использовать без причины:

- Подробнее;
- Нажмите сюда;
- Узнать всё;
- Начать путь.

## 13. Карточки

Базовая карточка:

- white surface;
- 1 px `#E5E7EB`;
- radius 16 px;
- padding 24 px;
- shadow small либо без тени.

Типы:

- service card;
- price card;
- project card;
- benefit card;
- article card;
- review card;
- contact card.

Каждый тип отличается контентом и иерархией, но не изобретает новый декоративный язык.

Запрещено делать оранжевую левую полосу обязательной для каждой карточки.

## 14. Иконки

Главный системный sprite:

`assets/brand/leader-icons.svg`

Иконки интерфейса:

- line style;
- 24×24;
- stroke около 2 px;
- rounded cap/join;
- без emoji;
- без случайного смешивания outline/filled/3D.

Логотипы VK, MAX и других платформ должны использовать их официальную графику, а не самодельную line-icon.

## 15. Реальные фотографии

Фото — главный визуальный доказательный слой сайта.

Приоритет кадров:

1. готовый объект;
2. общий план;
3. крупная деталь;
4. процесс монтажа;
5. производство;
6. до/после;
7. материал/технология.

Фотографии нельзя изменять так, чтобы клиент получил ложное представление об объекте, качестве или окружении.

AI допустим для абстрактной иллюстрации, схемы или рекламной концепции, но не выдаётся за выполненную работу.

Рекомендуемые ratio:

- hero — 16:9;
- project — 4:3;
- gallery — 3:2;
- square teaser — 1:1.

Текст поверх фото — только с overlay 35–55% и достаточным контрастом.

## 16. Портфолио и доказательства

Публичный сайт не должен создавать фиктивные кейсы.

Если подтверждённых данных недостаточно, использовать формат «Примеры задач» или «Как может выглядеть заказ», явно не выдавая сценарий за выполненный проект.

Настоящий case card:

- реальное фото;
- тип работы;
- объект/клиент, если можно публиковать;
- город/локация при необходимости;
- материалы/технология;
- 1 конкретный результат без выдуманных цифр.

Case detail:

задача → решение → материалы → процесс → результат → фото → следующий шаг.

## 17. Trust-system

На коммерческих страницах должны встречаться реальные сигналы доверия:

- настоящие работы;
- понятный процесс заказа;
- реальные контакты;
- понятная география работы;
- сроки и их зависимость от задачи;
- реальные способы производства/монтажа;
- объяснение, что делается самостоятельно, а что через подрядчиков, если это важно клиенту;
- отзывы только с подтверждённым источником;
- отсутствие фальшивых счётчиков и «10000 клиентов», если цифра не подтверждена.

## 18. Страница услуги

Рекомендуемый порядок:

1. Hero: что делаем + CTA;
2. какие задачи решает услуга;
3. варианты продукта/материала;
4. реальные примеры;
5. цена или принцип расчёта;
6. как проходит заказ;
7. сроки;
8. FAQ;
9. итоговый CTA.

SEO-текст не должен ломать визуальную иерархию. Длинный информационный блок размещается после основного коммерческого сценария.

## 19. Страница цен

Страница цен должна быть максимально рациональной.

Нужно показывать:

- что именно входит в цену;
- единицу измерения;
- минимальный заказ при наличии;
- что влияет на итог;
- что является ориентиром, а не офертой;
- CTA на расчёт.

Цена — orange/graphite акцент, а не жёлтая декоративная система.

Не скрывать критически важные условия в мелком сером тексте.

## 20. Формы заявок

Главный принцип — минимальное усилие клиента.

Первичная форма обычно должна содержать только необходимые поля:

- имя или обращение — если действительно нужно;
- телефон;
- задача/услуга;
- optional комментарий;
- optional файл/фото там, где это помогает расчёту.

Не запрашивать в первом контакте данные, которые сотрудник может уточнить позже.

Обязательные состояния:

- default;
- focus;
- valid;
- error;
- disabled;
- submitting;
- success;
- retry/error after submit.

Ошибка описывает, что сделать пользователю, а не внутреннюю инфраструктуру.

## 21. Тексты и Tone of Voice

Формула публичного текста:

задача клиента → конкретное действие агентства → ожидаемый результат.

Хорошо:

> Изготовим вывеску по вашему макету или подготовим дизайн с нуля. Перед запуском согласуем размер, материал, стоимость и срок.

Плохо:

> Создадим уникальное инновационное решение, которое выведет ваш бизнес на новый уровень.

Текст сайта:

- короткий;
- конкретный;
- без канцелярита;
- без обещаний без доказательств;
- без внутренней терминологии CRM/инфраструктуры;
- без SEO-спама.

## 22. Цены, сроки, телефоны

Цены:

- `от 5 000 ₽`;
- `5 000 ₽/м²`;
- `ориентировочная стоимость` там, где итог зависит от параметров.

Сроки:

- `от 2 рабочих дней`;
- `обычно 3–5 рабочих дней после согласования макета`;
- не писать «сделаем быстро», если срок не определён.

Телефон показывается в читаемом человеко-ориентированном формате, `tel:` содержит нормализованный номер.

## 23. FAQ, accordion и secondary content

FAQ используется для реальных возражений и вопросов, а не для искусственного увеличения SEO-объёма.

Каждый вопрос:

- один смысл;
- короткий заголовок;
- конкретный ответ;
- без скрытого основного CTA.

Summary/accordion должен иметь keyboard focus и работать без мыши.

## 24. Responsive

Mobile — не уменьшенная desktop-версия, а приоритетный рабочий сценарий.

На mobile:

- CTA остаётся заметным;
- телефон кликабелен;
- формы не требуют horizontal scroll;
- карточки переходят в 1 колонку;
- touch targets минимум 44 px;
- таблицы цен получают адаптивное представление;
- H1 не ломает экран;
- decorative elements упрощаются.

## 25. Accessibility

Минимум:

- контраст WCAG AA для основного текста и интерактивных элементов;
- `focus-visible`;
- semantic headings;
- alt для содержательных изображений;
- decorative SVG `aria-hidden=true`;
- label для полей;
- ошибки формы связаны с полями;
- интерактивы доступны с клавиатуры;
- `prefers-reduced-motion` поддерживается.

Orange не должен быть единственным способом показать состояние.

## 26. Motion

Допустимо:

- hover 160–200 ms;
- `translateY(-1px)` для кнопки;
- `translateY(-2px)` для карточки;
- фото scale до 1.02;
- fade/slide menu/dialog.

Не использовать:

- бесконечные фоновые анимации;
- bouncing CTA;
- тяжёлый parallax;
- обязательные reveal-анимации для чтения контента.

## 27. SEO и бренд

SEO не имеет права разрушать бренд.

Каждая страница должна иметь:

- уникальный title;
- уникальный description;
- один логичный H1;
- канонический URL;
- нормальную heading hierarchy;
- полезный текст для человека;
- внутренние ссылки только там, где они действительно помогают.

Не создавать отдельный визуальный стиль под SEO-страницы.

## 28. Производительность

Предпочтения:

- локальные SVG;
- WebP/AVIF для фото с fallback по необходимости;
- lazy load ниже fold;
- ограниченные CSS effects;
- без тяжёлых внешних font/runtime dependencies без явной пользы;
- shared CSS/tokens вместо копирования стилей на каждую страницу.

Новая бренд-функция не должна заметно ухудшать Core Web Vitals ради декора.

## 29. Техническая архитектура бренда

Новые/мигрируемые страницы должны постепенно опираться на:

- `assets/brand/leader-tokens.css`;
- `assets/brand/leader-components-v1.css`;
- `assets/brand/leader-icons.svg`;
- page-level CSS только для уникальной композиции страницы.

Запрещено создавать новый набор `--orange`, `--yellow`, `--primary-blue` и т. п., если значение уже есть в shared tokens.

Допустим временный compatibility mapping legacy variables → brand tokens во время миграции.

## 30. Правило безопасной миграции

Не переписывать весь сайт одним большим PR.

Порядок:

1. общий token/component foundation;
2. главная;
3. цены;
4. услуги;
5. service landing pages;
6. примеры/портфолио;
7. формы и request flows;
8. статьи/служебные публичные страницы;
9. удаление legacy CSS после подтверждения отсутствия зависимостей.

Каждый шаг должен сохранять SEO, формы, аналитику, accessibility и существующие URL.

## 31. Запрещённые паттерны для новых страниц

Не добавлять:

- yellow brand CTA;
- orange gradient как обязательный primary button;
- generic glass cards;
- 30+ px card radius;
- emoji service icons;
- fake reviews;
- fake portfolio;
- autoplay video with sound;
- pop-up сразу после открытия страницы;
- больше двух равнозначных primary CTA в одном блоке;
- внутренние технические термины в пользовательском тексте;
- скрытые или визуально слабые ошибки формы.

## 32. Definition of Done для публичной страницы

Страница считается соответствующей брендбуку, если:

- использует официальный логотип;
- использует shared brand colors/tokens;
- имеет понятную типографическую иерархию;
- не использует случайные emoji/icons;
- primary CTA orange и визуально один главный;
- cards/controls используют согласованные радиусы;
- mobile layout полноценен;
- focus/keyboard states работают;
- реальные работы не подменены фиктивными;
- текст конкретный и клиентский;
- форма, если есть, имеет success/error states;
- SEO и canonical не сломаны;
- нет новых remote dependencies без причины;
- CI и page-specific regression checks проходят.

## 33. Эталон восприятия

После миграции клиент должен воспринимать сайт так:

> «Это реальное современное рекламное агентство. Здесь понятно, что делают, можно увидеть качество, понять порядок работы и быстро получить расчёт».

Если страница выглядит эффектно, но ухудшает это восприятие, решение не соответствует брендбуку.
