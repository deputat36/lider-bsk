# CRM profile-first boot browser check — 2026-07-24

Связано с #203.

## Что проверяется

Настоящий модуль `crm/v4/assets/v4/auth.js` выполняется в headless Chrome. Временное окружение подменяет только внешние зависимости авторизации и не обращается к Supabase.

Пять сценариев:

1. Активный профиль — CRM открывается, событие `leader-v4:crm-ready` испускается один раз.
2. Неактивный профиль — рабочая область остаётся закрытой, выход доступен.
3. Отсутствующий профиль — вызывается `ensure_profile`, созданный pending-профиль не открывает CRM.
4. Ошибка сети при чтении профиля — CRM остаётся закрытой, показывается отдельная ошибка.
5. Просроченная локальная сессия — локальная сессия очищается, форма входа возвращается.

## Границы безопасности

- реальные пользователи не создаются;
- пароли и токены не используются;
- база данных не читается и не изменяется;
- внешние сетевые запросы не выполняются;
- production и staging Supabase не затрагиваются;
- проверка имеет только `contents: read`.

## Критерии прохождения

- рабочая область видна только активному профилю;
- `leader-v4:crm-ready` отсутствует во всех заблокированных сценариях;
- неактивный, pending и сетевой сценарии сохраняют доступ к выходу;
- просроченная сессия очищает локальное хранилище;
- настоящий `auth.js` проходит браузерное выполнение без ошибок.
