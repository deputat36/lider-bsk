# Проверка способа связи на странице заявки — 2026-07-13

Контур: только `https://www.lider-bsk.ru/request.html`.

## Проблема

Общая форма позволяет выбрать способы:

- «Написать ВКонтакте»;
- «Написать на email».

Телефон при этом обязателен, но без email или ссылки на профиль сотрудник не сможет выполнить именно выбранный клиентом способ связи.

## Реализация

Для `request.html` добавлен локальный sidecar:

- `assets/public-request-contact-method-v1.js?v=1`;
- `assets/public-request-contact-method-v1.css?v=1`.

Страница сохраняет существующий основной контракт и два канонических внешних скрипта:

1. `assets/public-lead-reference-v1.js?v=1`;
2. `assets/public-lead-form.js?v=5`.

После них небольшой bootstrap создаёт `<script>` для `assets/public-request-contact-method-v1.js?v=1`. Sidecar после загрузки подключает отдельную таблицу стилей `assets/public-request-contact-method-v1.css?v=1` через элемент `<link>`.

Такой способ сохраняет:

- прежний marker страницы `20260628-clarity-2`;
- порядок `reference helper → shared form`;
- существующий контракт стабильного `request_id`;
- две основные внешние таблицы стилей страницы;
- отсутствие inline CSS.

Sidecar не изменяет `assets/public-lead-form.js`, Edge Function или структуру payload.

## Поведение

1. Для «Написать на email» поле становится обязательным и получает подпись «Email для ответа».
2. Для «Написать ВКонтакте» поле становится обязательным и получает подпись «Ссылка на профиль ВКонтакте».
3. Подробные поля автоматически раскрываются, если выбран один из этих способов.
4. При пустом обязательном поле отправка останавливается до вызова общей submit-логики.
5. Браузер показывает понятную ошибку рядом с полем.
6. Для звонка, MAX по указанному номеру и любого удобного способа дополнительное поле остаётся необязательным.
7. Ошибка выбора фиксируется только аналитическим событием `contact_detail_missing`; POST в `leader-public-lead` не выполняется.

## Порядок выполнения

На странице сохраняется последовательность:

1. reference helper подготавливает стабильный `request_id`;
2. shared form монтирует форму и основную submit-логику;
3. bootstrap загружает contact-method sidecar;
4. sidecar подключает свой CSS и регистрирует capture-submit проверку.

Capture-listener выполняется до общей submit-логики. При отсутствии обязательного email или ссылки ВКонтакте он останавливает событие до сетевого запроса.

## Ручная browser/Network проверка

### Email без адреса

1. Открыть `request.html` с DevTools → Network.
2. Нажать «Добавить подробности».
3. Выбрать «Написать на email».
4. Не заполнять поле email.
5. Нажать «Отправить заявку».

Ожидается:

- подробности открыты;
- поле помечено обязательным;
- показано сообщение «Укажите email для выбранного способа связи»;
- POST в `leader-public-lead` отсутствует;
- production-заявка не создаётся.

### ВКонтакте без ссылки

Повторить сценарий с «Написать ВКонтакте».

Ожидается:

- подпись «Ссылка на профиль ВКонтакте»;
- сообщение «Укажите ссылку на профиль ВКонтакте»;
- POST отсутствует.

### Валидный дополнительный контакт

1. Выбрать email или ВКонтакте.
2. Заполнить соответствующее поле.
3. Остальные данные заполнять только при отдельном разрешении на production E2E.

До такого разрешения не нажимать финальную отправку с валидными данными, поскольку она создаёт строку в `leader_leads`.

### Способы по телефону

Для вариантов:

- «Позвонить по указанному номеру»;
- «Написать в MAX по указанному номеру»;
- «Любой удобный способ»

дополнительное поле не должно блокировать отправку.

## Границы

- общий form JS не меняется;
- payload и `request_id` не меняются;
- Edge Function и Supabase production не меняются;
- CRM UI и `nav_*` не затрагиваются;
- внедрение на остальные посадочные страницы потребует отдельного общего cache-релиза формы.
