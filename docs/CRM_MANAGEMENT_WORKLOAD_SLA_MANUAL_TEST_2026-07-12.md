# CRM management workload/SLA — manual browser test

Дата: 2026-07-12.

Контур: CRM v4 РА «Лидер».

Связано с: #200, #205.

## Что проверяется

В управленческом дашборде появился read-only блок «Нагрузка и SLA по ответственным».

SLA считается выполненным, когда у активной заявки назначен следующий контакт и его время ещё не просрочено. Терминальные статусы заявки исключаются через canonical status registry.

Панель использует только минимальные поля:

- `leader_leads`: `id,status,assigned_to,next_contact_at,created_at,service,source`;
- `leader_user_profiles`: `user_id,full_name,role,is_active`.

Панель не должна запрашивать телефоны, email, сообщения, имена клиентов, внутренние комментарии или финансовые суммы.

## Роли

1. Войти под owner/admin.
2. Убедиться, что доступна вкладка «Дашборд».
3. Открыть управленческий дашборд.
4. Под manager, designer, production, installer или contractor панель не должна предоставлять обход скрытой вкладки management_dashboard.

## Основной сценарий

1. Нажать Ctrl + F5.
2. Открыть вкладку «Дашборд».
3. Дождаться базовой управленческой сводки.
4. Ниже основных карточек должен появиться блок «Нагрузка и SLA по ответственным».
5. Проверить агрегаты:
   - активные заявки;
   - без ответственного;
   - нарушения SLA;
   - покрытие SLA;
   - контакты сегодня.
6. Проверить строки по каждому активному owner/admin/manager:
   - активных заявок;
   - без следующего контакта;
   - просроченных контактов;
   - контактов сегодня;
   - процент SLA;
   - возраст старейшей активной заявки.
7. Строка «Без ответственного» должна отображаться отдельно.
8. Нажать «Открыть очередь» у непустой строки.
9. В модальном окне должны отображаться только услуга, источник, статус, короткий ID заявки, дата создания и следующий контакт.
10. В очереди намеренно не отображаются имя клиента, телефон, email, сообщение, внутренние комментарии и финансовые суммы.
11. Нажать «Открыть заявку» и проверить переход в карточку заявки.
12. Закрыть модальное окно кнопкой, кликом по фону и клавишей Escape.
13. Нажать «Обновить SLA» и затем общую кнопку обновления дашборда. Панель должна обновиться без дублирования DOM-блока.

## Network checklist

Открыть DevTools → Network и очистить журнал после полной загрузки CRM.

При открытии workload/SLA допустимы только read-only GET/SELECT запросы:

- к `leader_leads` с минимальным набором полей;
- к `leader_user_profiles` с минимальным набором полей.

Проверить:

- нет POST;
- нет PATCH;
- нет DELETE;
- нет RPC;
- нет Edge Function write-команд;
- нет INSERT, UPDATE, UPSERT или DELETE к `leader_*`;
- открытие очереди не создаёт новый сетевой запрос;
- открытие карточки заявки использует обычный существующий маршрут CRM.

## Ошибки и деградация

1. При отказе одного из read-only запросов панель должна показать понятную ошибку.
2. Базовый управленческий дашборд при этом не должен исчезать.
3. Повторная кнопка должна разрешать новый read-only запрос.
4. Ошибка панели не должна менять рабочие данные.

## Адаптивность

Проверить ширины:

- 1280 px;
- 768 px;
- 390 px.

На узком экране строки workload должны перестраиваться в карточки, а кнопки оставаться доступными без горизонтального выхода за экран.

## Production boundary

- никакие production-строки не создаются и не изменяются;
- Supabase DDL/DML не выполняются;
- migrations, RLS, grants, Auth, Storage и Edge Functions не меняются;
- `nav_*`, `nav-*`, `parket-*`, `broker-*` не затрагиваются;
- панель является только read-only операционным представлением;
- любые автоматические назначения, SLA gates, backfill или серверные права требуют отдельного approval.
