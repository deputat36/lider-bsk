# Сбор материалов для публичного портфолио — 2026-07-13

Связано: issue #235.

## Цель

Собрать 6–10 реальных выполненных заказов РА «Лидер» так, чтобы их можно было безопасно использовать на публичном сайте без вымышленных результатов, нарушения конфиденциальности и повторного запроса базовых сведений.

Этот документ является формой сбора доказательств. Он не означает разрешение на публикацию до заполнения поля «Разрешение» по каждому кейсу.

## Общие правила

- использовать только реально выполненные работы;
- не придумывать рост продаж, заявок, охват, экономию, сроки и отзывы;
- не публиковать имя клиента, логотип, адрес, автомобильный номер, телефон или людей без разрешения;
- исходные фотографии хранить отдельно от оптимизированных web-копий;
- перед публикацией удалить EXIF-геолокацию и проверить фон фотографии;
- один заказ может использоваться только как один кейс, даже если у него несколько фотографий;
- срок изготовления указывать только при подтверждении документом или владельцем процесса;
- отзыв использовать только дословно, с разрешением автора и без персональных данных;
- неизвестное значение отмечать `не подтверждено`, а не заполнять предположением.

### Фактический blocker

В текущем workspace и репозитории нет исходных фотографий этих объектов. Названия и описания слотов получены из задания, не из просмотра изображений. Размеры, финальный alt и source_file остаются `null`. Фотографии не заменяются AI/stock, пустые карточки посетителям не показываются.

Записи могут относиться к одному заказу (например, БОРМАШ / Завод БОРМАШ или Цветочная база / Цветочная витрина). После просмотра оригиналов проверить это и объединить совпадения до публикации; число записей не является числом подтверждённых уникальных кейсов.

### Подключение полученных файлов

1. Сопоставить оригинал со слотом, проверить фактическое содержание и возможные дубли.
2. Создать оптимизированную web-копию по `expected_web_path`; исходник хранить отдельно. Не изменять содержание объекта.
3. Заполнить `source_file` как имя исходного файла без локального абсолютного пути, `width`, `height` и осмысленный `alt` после просмотра. Удалить неиспользованные слоты.
4. Выбрать готовые записи для отдельного PR карточек на `primery-rabot-kejsy.html`, главной и указанных страницах услуг. `publish: true` требует всех файлов и метаданных; само по себе это поле ничего не публикует.
5. Использовать обычный `figure`/`img` с width/height, lazy-loading ниже первого экрана и подписью о фактически выполненной работе. Не добавлять даты, цены и результаты без источника.
6. Проверить визуально desktop/mobile, crop, alt и размеры загрузки. Закрыть #235 только после реальной публикации фотографий.

Регрессионная проверка: `python tools/check_public_portfolio_manifest.py`; включена в существующий Public site audit check.

## Минимум для публикации одного кейса

Кейс допускается к публикации, когда одновременно есть:

1. подтверждённая задача;
2. подтверждённый перечень выполненного;
3. минимум одна реальная фотография с правом публикации;
4. решение о раскрытии или скрытии клиента;
5. осмысленный alt-текст;
6. ссылка на релевантную услугу;
7. финальная проверка персональных данных.

Срок, цена, отзыв и измеримый результат не являются обязательными. Их отсутствие безопаснее неподтверждённого утверждения.

## Следующее действие после заполнения

После получения хотя бы одной готовой карточки (не требуется ждать шесть):

1. создать отдельную ветку от актуального `main`;
2. оптимизировать изображения и зафиксировать их размеры;
3. обновить `primery-rabot-kejsy.html` небольшим PR;
4. добавить 3–6 подтверждённых работ на главную;
5. создать тематические Open Graph изображения только из разрешённых материалов;
6. проверить мобильный вид, alt-тексты, скорость и structured data;
7. закрыть issue #235 только после публикации и проверки production-страниц.

CRM UI, `nav_*`, Supabase schema, RLS, Edge Functions и production data этим сбором материалов не изменяются.
