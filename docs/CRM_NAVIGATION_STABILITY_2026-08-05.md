# Стабилизация меню и вкладок CRM v4 — 2026-08-05

## Подтверждённый симптом

Рабочая CRM реагировала на меню с задержкой, а отдельные вкладки могли оставаться визуально пустыми.

## Фактическая причина

Production API logs показали, что сразу после входа браузер одновременно запрашивал данные заявок, потребностей, расчётов, КП, заказов, производства, монтажа, пользователей, расходов и дизайн-задач. CRM-запросы возвращали HTTP 200, поэтому отказ Supabase не подтверждён.

Исходный frontend одновременно:

- загружал более 30 ES-модулей;
- открывал тяжёлый дашборд по умолчанию для owner/admin;
- повторно перестраивал DOM меню по нескольким событиям и таймерам;
- допускал параллельное управление вкладками центральным router и отдельными модулями.

## Аварийный source-only пакет

- при отсутствии явного URL открывается разрешённая вкладка `leads`;
- меню строится один раз и далее только синхронизирует видимость и active state;
- повторные menu sync объединяются через `requestAnimationFrame`;
- повторный переход в ту же вкладку в одном цикле событий подавляется;
- для неинициализированной вкладки появляется понятное сообщение и кнопка повторения;
- добавлен CI source-contract.

## Граница пакета

Этот пакет не реализует полную lazy-loading архитектуру и не меняет Supabase. Следующий этап должен вынести тяжёлые вкладки в dynamic import, оставить одного владельца навигации и провести авторизованный Browser/Network acceptance.

Production данные, Auth, RLS, grants, Edge Functions, `nav_*`, `parket_*`, `broker_*` и `newbuild_*` не изменялись.
