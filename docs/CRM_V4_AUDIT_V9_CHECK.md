# Проверка аудита публичной заявки v9

Дата: 2026-07-10.

Контур проверки:

`request.html → leader-public-lead v9 → leader_leads → leader_public_lead_audit → leader_request_trace → CRM v4`.

## Проверка новой заявки

1. Открыть `https://www.lider-bsk.ru/request.html`.
2. Обновить страницу без кеша.
3. Отправить заявку с пометкой `Тест CRM v4 audit v9`.
4. Скопировать показанный сайтом номер обращения `request_id`.
5. Открыть основной CRM-контур и раздел `Аудит заявок`.
6. Обновить аудит и найти событие по `request_id`.
7. Проверить статус `Принято` и причину `lead_insert_created`.
8. Вставить номер в поле `Проверить request_id`.
9. Убедиться, что отображается `Цепочка полная`.
10. Открыть заявку из результата трассировки и сопоставить телефон, услугу и страницу источника.

## Проверка дубля

Повторный запрос с тем же `request_id` должен:

- вернуть успешный ответ с `duplicate: true`;
- не создать вторую строку в `leader_leads`;
- создать audit-событие `duplicate` с причиной `request_id_conflict`;
- сохранить тот же номер обращения в сообщении сайта.

## Проверка honeypot

Запрос с заполненным полем `website` должен:

- вернуть безопасный успешный ответ;
- не создать заявку в `leader_leads`;
- создать audit-событие `suspicious` с причиной `honeypot_filled`;
- отображаться в трассировке как `Audit без заявки`.

## Проверка отклонённого запроса

Запрос без телефона и сообщения должен:

- вернуть HTTP 400 и код `phone_or_message_required`;
- создать audit-событие `rejected`;
- не создать заявку.

## Что считать ошибкой

- сайт не показывает `request_id`;
- `request_id` сайта отличается от номера в CRM;
- корректная новая заявка не даёт статус `Цепочка полная`;
- дубль создаёт вторую заявку;
- honeypot создаёт заявку;
- audit-событие отсутствует;
- CRM не позволяет открыть найденную заявку;
- виджет продолжает показывать устаревшую маркировку v8.
