# Проверка отображения логотипа публичного сайта — 16 июля 2026 года

## Что проверено

Проверены:

- фирменный знак в шапках ключевых публичных страниц;
- общий CSS публичной формы и шапки;
- существующие брендовые файлы в `assets/brand`;
- размеры на широком экране и телефоне;
- отсутствие двойного знака и зависимости от JavaScript;
- сохранение живого текста «Лидер» для доступности и поисковых систем.

## Обнаруженная проблема

В репозитории существовал файл `assets/brand/logo-lider-light.svg`, но он не подходит для горизонтальной шапки сайта:

- холст имеет размер 300 × 271 и почти квадратную пропорцию;
- внутри SVG размещено растровое PNG-изображение через `data:image/png;base64`;
- при помещении такого файла в область примерно 150 × 64 логотип становится слишком маленьким либо увеличивает высоту шапки;
- предыдущая попытка подключить его как background уже была отменена из-за проблем отображения и переполнения на ноутбуках.

Общий CSS после этого снова показывал CSS-нарисованный знак только на страницах с полной HTML-разметкой. На страницах с сокращённым брендом отображался только текст, поэтому фирменное представление было непоследовательным.

## Принятое решение

Добавлен отдельный чистый векторный знак:

`assets/brand/logo-lider-mark.svg`

Контракт отображения:

- широкие экраны: знак 50 × 44;
- мобильные экраны: знак 40 × 36;
- знак выводится через `.header .brand::before`;
- старый inline-блок `.mark` скрывается, чтобы знак не дублировался;
- название «Лидер» и подпись остаются обычным HTML-текстом;
- JavaScript для логотипа не используется;
- внешний файл, base64-картинка и сторонний хостинг не требуются.

Такой вариант сохраняет текущую визуальную идентичность: оранжевый восходящий знак, тёмный элемент и текстовое название агентства. При масштабировании в браузере знак остаётся резким.

## Какие страницы получают исправление

Исправление автоматически применяется ко всем публичным страницам, которые:

1. содержат элемент `.header .brand`;
2. подключают `assets/public-lead-form.css`.

В обязательный контракт включены:

- `index.html`;
- `request.html`;
- `uslugi.html`;
- `primery-rabot-kejsy.html`.

Остальные страницы с такой же структурой также получают знак без отдельного изменения HTML.

## Автоматическая защита

`tools/check_public_logo_contract.py` проверяет:

- валидность SVG;
- точный `viewBox` и размеры;
- наличие фирменных цветов;
- отсутствие raster/base64, `<image>`, `<script>` и внешних ресурсов;
- desktop/mobile размеры в CSS;
- отсутствие ссылки на `logo-lider-light.svg` в публичных HTML и CSS;
- наличие бренда и общего CSS на ключевых страницах;
- отсутствие двойного знака.

Проверка запускается workflow:

`.github/workflows/public-logo-display-check.yml`

## Ручная визуальная проверка после публикации

Проверить главную, заявку, каталог услуг и примеры задач:

- 1440 px — знак и название находятся на одной линии, шапка не растянута;
- 1280 px — меню и телефон не перекрывают бренд;
- 1024 px — мобильная навигация включается без горизонтального скролла;
- 390 px и 360 px — знак не обрезан, название читается, дублирования нет;
- масштаб браузера 125% и 150% — шапка переносится по действующему responsive-контракту без переполнения.

## Supabase

Изменение относится только к статическим файлам публичного сайта. Supabase production и staging не изменяются: база, Auth, RLS, Edge Functions и данные не затрагиваются.
