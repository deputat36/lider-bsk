## Задача

CRM должна выглядеть как рабочая часть бренда РА «Лидер», а не как отдельная синяя административная панель.

Главный принцип:

`одна рабочая ситуация → одно главное действие → вторичные действия не конкурируют с ним`.

## Визуальная система

- основной фон: глубокий графит `#090A0C`;
- рабочая поверхность: белая;
- главный акцент: `#FF6A00`;
- активное действие: градиент `#FF6A00 → #FF8126`;
- предупреждение: `#FFF7ED / #9A3412`;
- успех: `#DCFCE7 / #166534`;
- ошибка: `#FEE2E2 / #991B1B`;
- шрифт: Montserrat;
- заголовки: 900, плотная типографика;
- кнопки и фильтры: pill или радиус 12–16 px;
- карточки: радиус 16–24 px;
- модальные карточки: радиус 20–28 px.

## Рабочая навигация

Основные разделы:

1. Управление
2. Аудит заявок
3. Заявки
4. Заказы
5. Производство
6. Монтаж
7. Финансы
8. Карточка заказа

На узком экране вкладки не переносятся хаотично: используется горизонтальная прокрутка.

## Иерархия действий

### Главное действие

Оранжевое. На одном смысловом блоке должно быть одно главное действие:

- обновить данные;
- открыть заявку;
- сохранить изменение;
- создать заказ;
- перевести статус;
- запустить расчёт;
- отправить КП.

### Вторичные действия

Белые с графитовым или оранжево-коричневым текстом:

- открыть детали;
- скопировать номер;
- проверить цепочку;
- раскрыть историю;
- перейти к связанному объекту;
- закрыть окно.

### Статусы

Статус не оформляется как главное действие. Цвет используется только как семантический сигнал.

## Безопасность

Дизайн не меняет:

- Supabase-запросы;
- таблицы `leader_*`;
- RLS;
- role guards;
- список разрешённых полей;
- скрытие себестоимости;
- скрытие внутренних комментариев;
- registry статусов;
- правила переходов;
- расчёт SLA;
- финансовые формулы;
- создание заявок и заказов.

CSS-адаптеры используют существующие классы и `!important`, потому что часть модулей добавляет локальные `<style>` после загрузки основной страницы.

## Чек-лист визуальной приёмки

### Общий интерфейс

- [ ] Нет синей темы в основных и динамических разделах.
- [ ] На блоке не более одного оранжевого главного действия.
- [ ] Вторичные кнопки читаются, но не конкурируют с главным действием.
- [ ] Клавиатурный фокус заметен.
- [ ] Мобильные вкладки прокручиваются горизонтально.
- [ ] Текст не обрезается при длинных номерах и названиях.

### Роли

- [ ] Менеджер не видит закрытые финансовые данные.
- [ ] Производство видит только разрешённые задания и поля.
- [ ] Монтаж видит только разрешённые задания и поля.
- [ ] Внутренние комментарии скрыты для неподходящей роли.
- [ ] Администратор сохраняет полный доступ.

### Сценарии

- [ ] Создать обращение вручную.
- [ ] Открыть заявку и добавить событие в таймлайн.
- [ ] Создать/открыть заказ.
- [ ] Открыть сохранённый расчёт и защищённую версию.
- [ ] Открыть производственное задание.
- [ ] Открыть монтажное задание.
- [ ] Проверить просроченные и предупреждающие состояния.
- [ ] Проверить `request_id` в аудите.
