# Public client copy and infrastructure boundary

Дата исходного аудита: 2026-07-12.

Актуализация инфраструктурной границы: 2026-07-13.

Scope: public site only.

## Цель

Клиентский сайт должен объяснять результат для заказчика, а не внутреннее устройство РА «Лидер», базы данных или серверного контура обработки заявки.

В корневых публичных HTML запрещены внутренние или технические термины двух групп.

### Внутренняя экономика и процессы

- CRM;
- себестоимость;
- маржа;
- «рабочий контур» применительно к обработке заявки.

### Инфраструктура публичной формы

- Supabase;
- Edge Function;
- `request_id` и `request-id`;
- `leader-public-lead`;
- project ref `ofewxuqfjhamgerwzull`;
- таблицы `leader_leads` и `leader_public_lead_audit`;
- внутренние поля `source_page_path`, `submitted_at`, `phone_normalized`;
- `service role`, `anon key` и `anonymous key`;
- RLS и Row Level Security;
- формулировка `API endpoint`.

Общий термин API намеренно не запрещён: он может описывать реальную клиентскую услугу или интеграцию. Запрещаются только конкретные внутренние идентификаторы и инфраструктурные формулировки.

Внутренние CRM-страницы, `nav_*`, техническая документация, внешние JS-исходники формы и серверные функции находятся вне этого контракта.

## Исправленные страницы исходного аудита

Первый полный source-аудит выявил восемь публичных файлов с девятью остаточными упоминаниями CRM:

- `bannery-borisoglebsk.html`;
- `faq.html` — два фрагмента;
- `kak-prohodit-zakaz.html`;
- `outdoor-advertising-borisoglebsk.html`;
- `pechat-na-plenke-borisoglebsk.html`;
- `privacy.html`;
- `reklama-dlya-biznesa.html`;
- `utm-links.html`.

Дополнительная проверка страницы контактов выявила формулировку «заявка попадёт в рабочий контур». Она заменена на фактический клиентский результат: после отправки появляется номер обращения, затем специалист связывается для уточнения деталей.

Проверка 2026-07-13 не выявила инфраструктурных маркеров в корневых клиентских HTML. Расширенный checker добавлен как защита от будущей регрессии.

## Принцип замены

Вместо внутреннего инструмента, таблицы или процесса клиент видит:

- номер обращения после отправки;
- сохранение описания задачи;
- передачу заявки специалисту;
- возможность быстро продолжить работу после уточнений;
- понятное сообщение об успешной отправке или ошибке;
- политику обработки данных без раскрытия технической реализации.

Смысл формы, расчёта, UTM-меток и политики обработки персональных данных сохранён.

## Постоянная проверка

`tools/check_public_client_copy_boundary.py` сканирует все корневые `*.html`.

При нарушении он выводит:

- имя файла;
- номер строки;
- запрещённый термин;
- сокращённый фрагмент исходника.

Workflow:

- `.github/workflows/public-client-copy-boundary-check.yml`.

## Границы

Не изменялись:

- публичные HTML и клиентские тексты в рамках актуализации 2026-07-13;
- CRM UI;
- `nav_*` и `nav_v2_*`;
- общая форма, payload и `request_id` contract;
- Supabase Edge Functions;
- schema, RLS, grants, policies, Auth и production data;
- цены, состав услуг и логика формы.
