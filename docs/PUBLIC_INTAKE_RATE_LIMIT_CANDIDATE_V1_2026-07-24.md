# Public intake rate-limit candidate v1 — 2026-07-24

Связано с #201 и source-only service-role cutover.

Статус: source-only. Production не изменён.

## Задача

Не позволять автоматическим отправителям массово создавать заявки и audit-записи после закрытия прямого anon INSERT.

## Принцип

- окно — 5 минут;
- не более 20 принятых попыток с одного IP-хеша;
- не более 5 принятых попыток с одного телефонного хеша;
- повтор с тем же `request_id` не расходует лимит повторно;
- при превышении возвращается HTTP 429 и `retry_after_seconds`;
- если rate-limit RPC недоступен, Edge закрывается с HTTP 503, а не пропускает запись без контроля.

## Конфиденциальность

- исходный IP не записывается в БД, audit или логи;
- IP и нормализованный телефон хешируются SHA-256;
- используется отдельная приватная соль `LEADER_PUBLIC_RATE_LIMIT_SALT` длиной не менее 16 символов;
- в таблице хранятся только `request_id`, два хеша и время;
- записи старше двух дней удаляются opportunistic cleanup внутри RPC.

## Порядок применения

Каждый production-шаг требует отдельного разрешения владельца.

1. Создать приватную случайную соль и сохранить как Edge secret, не выводя значение в журнал.
2. Применить `20260724_02_public_intake_rate_limit_candidate.sql`.
3. Проверить, что RPC доступна только service role.
4. Развернуть Edge candidate вместе с `rate-limit.ts`.
5. Проверить один обычный запрос и один повтор с тем же `request_id`.
6. В изолированном контролируемом тесте подтвердить 429 после лимита, не используя клиентские телефоны.
7. Убедиться, что raw IP отсутствует в таблице, audit и function logs.
8. После этого выполнять основной service-role cutover и закрывать anon INSERT.

## Stop conditions

- нет приватной соли;
- RPC доступна `anon` или `authenticated`;
- raw IP появляется в БД или журнале;
- повтор того же `request_id` расходует квоту повторно;
- недоступная RPC приводит к обходу rate limit;
- обычная заявка или ручное создание заявки CRM перестали работать;
- rollback не готов до начала production-шагов.

## Rollback

1. Вернуть предыдущую Edge version без вызова rate-limit RPC.
2. Применить rollback candidate `20260724_02_public_intake_rate_limit_candidate_rollback.sql`.
3. Убедиться, что публичная форма снова проходит обычный маршрут.
4. Не изменять и не удалять заявки, созданные до rollback.

## Границы

- source merge не создаёт secret;
- source merge не применяет SQL;
- source merge не развёртывает Edge Function;
- production load test не выполняется без отдельного разрешения;
- реальные клиентские данные для теста не используются.
