## Данные и безопасность

Финальный read-only срез production: **19 заявок, 17 клиентов, 69 позиций прайса, 2 заказа, 1 оплата, 0 расходов**. Новых постоянных тестовых подписок, notification events/outbox, документов, номеров, receipts, возвратов, переносов и подтверждений расходов — 0. Native probes выполнялись с ROLLBACK. Исторические данные автоматически не удалялись и не переклассифицировались.

Публичный Data API с publishable key: `net` и `leader_private` возвращают 406 `Invalid schema`; доступны только `public, graphql_public`. Анонимный SELECT документов и подрядных запросов — 401 `permission denied`. Браузер не имеет EXECUTE на новые служебные RPC. Для публичной формы сохранён только защищённый Edge, для сотрудника — разрешённый ручной ввод.

Advisors не добавили новых security findings: 9 INFO RLS без policy, 53 WARN executable SECURITY DEFINER и 1 WARN leaked-password protection относятся к общему проекту и требуют отдельной оценки области действия. Закрытая private-таблица без browser grants и RLS policy не означает открытый доступ. В публичных Leader-функциях, проверенных запросом к pg_proc, доступных authenticated SECURITY DEFINER не обнаружено; это не снимает замечания других схем/проектов.

Все новые Leader FK покрыты индексами: общее число unindexed FK сократилось с 26 до 12, оставшиеся относятся к другим проектам. Старые 27 `auth_rls_initplan` и 7 `multiple_permissive_policies` остаются. 149 unused-index INFO после установки на пустые таблицы не являются основанием удалять индексы. Другие проекты общей базы и глобальный Auth не менялись.

Ссылки на рекомендации Supabase: [FK](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys), [RLS initplan](https://supabase.com/docs/guides/database/database-linter?lint=0003_auth_rls_initplan), [несколько policies](https://supabase.com/docs/guides/database/database-linter?lint=0006_multiple_permissive_policies), [SECURITY DEFINER](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable), [защита паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

В legacy-схеме остаются browser DML grants на 28 Leader-таблиц. Grants сами по себе не доказывают обход RLS, но скрытые кнопки не заменяют серверные ограничения. Нельзя считать #202/#204 полностью закрытыми по новым модулям: следующий security этап — положительная и отрицательная матрица каждого старого модуля, затем постепенный отзыв лишних writes с сохранением рабочего интерфейса.

## Почему работа теперь легче восстанавливается

1. WORK_CURRENT содержит только актуальные факт, следующий шаг и ограничения; STATUS остаётся хронологией. После обрыва не нужен новый полный аудит.
2. Source сохраняется удалённым commit до изменения сервера; миграция и Edge затем сверяются независимым readback. Потерянный ответ не считается неуспешной установкой.
3. Команды используют стабильный request_id и точный payload. Восстановление неизвестного результата не создаёт вторую заявку, документ или финансовую операцию.
4. В сетевых вызовах и SQL есть deadline/lock timeout; в очереди — lease, expiration и предел повторов. Одинаковая ошибка не повторяется бесконечно.
5. Все оставшиеся `playwright install --with-deps` удалены из workflows. Browser jobs используют образ Playwright 1.55.0 по digest; системные пакеты и Chromium заново не скачиваются. Ограничены runtime и параллельные устаревшие запуски. Небольшой npm-пакет всё ещё загружается из registry.
6. Убрана лишняя JSR-загрузка только типов из новых Edge; источник уже вызывал bundle timeout. Зависимость web-push зафиксирована и проверена.
7. Для 19 изменённых модулей CRM обновлён importmap release, в том числе legacy aliases: браузер не смешивает старые и новые singleton transport. Не выполняется массовая очистка localStorage или регистраций других приложений.

Эти меры уменьшают риск повторов и потери прогресса. Полностью исключить сбой платформы или соединения нельзя; точка восстановления хранится вне текущего чата.
