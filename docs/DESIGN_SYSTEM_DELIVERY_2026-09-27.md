# Единая визуальная система — 27.09.2026

Источник истины — `deputat36/lider-bsk`, поверх main с PR559. Работа развивает существующие страницы и CRM v4.

## Логотип

Найден PNG, предоставленный владельцем 17.07.2026: чёрная надпись, оранжевый знак. Оригинал сохранён без изменений в `assets/brand/source/logo-lider-owner-black-20260717.png`; SHA256 `3bf3bb59ac90cdfe535ec2c66339462d5c7d90199b453563226129744bcef833`. Белая версия также архивирована. Ранее опубликованная горизонтальная реконструкция не соответствует этому оригиналу.

Исходный PNG имеет непрозрачную шахматную подложку. Digital-файл использует оптимизированный WebP 640 px, тот же растр внутри SVG и alpha-маску подложки; знак и надпись не обводились и не набирались заново. `tools/build_brand_logo.py` воспроизводит SVG. Это **не векторный master**. Для качественной большой печати нужен оригинальный SVG/CDR либо PNG с настоящей прозрачностью.

Один файл используется в публичных шапках, CRM, КП и OG; favicon показывает тот же знак. На тёмном фоне применяется белая плашка. `logo-lider-light.svg` — совместимый reference only, не автоматически перекрашенная версия. Июньский архив со встроенным повреждённым PNG не публикуется. Guard проверяет hash оригинала, встроенный WebP, отсутствие перерисованных path/text и использование canonical asset в шапках/CRM/КП.

## Система в коде

- Общие `leader-tokens.css/json`: цвета действия и текста, нейтрали, статусы, размеры текста, spacing, радиусы, focus, touch target 44 px.
- Manrope хранится локально: variable WOFF2 Latin/Cyrillic, 33 488 байт; `font-display: swap`. Источник Google Fonts `google/fonts/ofl/manrope/Manrope[wght].ttf`, blob `75274da58537d6123b14f2cd0c355ad4681fc2b3`; лицензия OFL сохранена рядом. Внешнего font-запроса нет.
- Публичный `public-product-system.css` подключается **последним**. Это существенное правило: предыдущие слои с равной specificity возвращали белые буквы на оранжевой кнопке и увеличенные заголовки.
- Главная: компактная шапка в одну строку на широком экране, H1 до 48 px, спокойный графитовый hero, читаемые CTA. Формы светлые, с видимыми labels, focus и полями не меньше 16 px на телефоне.
- CRM: общие токены, нейтральные карточки, компактная шапка, меньше декоративных полос/градиентов, контрастные статусы и кнопки. Обучение свёрнуто по умолчанию; явно сохранённый выбор пользователя соблюдается. Lazy-loader и бизнес-контракты сохранены.
- КП: исходный логотип заменяет CSS-имитацию; добавлены переносы длинных строк и правила повторения шапки таблицы/разрывов печати. Анонимность клиентского документа проверена существующим behavior test.

## Проверки

`tools/test_product_visual_browser.mjs`: Chromium + axe-core 4.10.3, 5 экранов × 5 ширин (360, 390, 768, 1024, 1440). Главная, каталог, вывески, заявка и изолированный CRM-стенд: 25/25 без найденных WCAG 2 A/AA / 2.1 AA нарушений, JS errors, unexpected network, horizontal overflow. JSON: `docs/evidence/product-visual-2026-09-27.json`. Это автоматическая проверка, не полная ручная сертификация доступности.

Отдельно настоящий browser test главной, каталога и услуги проверил клавиатуру, Escape, мобильное меню, no-JS ссылки, service preset и сохранение черновика. Проверки retry/UTM/service выполняют реальный обработчик формы с перехваченным HTTP, без отправки production-заявок.

Измеренный объём начальных ресурсов в изолированном локальном браузере: публичные экраны около 143–154 КБ, CRM-стенд около 91 КБ; общий шрифт 33.5 КБ, один SVG логотипа менее 40 КБ, OG PNG 57.5 КБ. Это не Lighthouse score и не измерение реального мобильного интернета. Метрика изолирована в тесте; доставку её событий в кабинет этот тест не доказывает.

Скриншоты и подробный отчёт сохраняются artifact `product-system-browser` в существующем CI `CRM brand foundations v2 check`. Authenticated staging проверяется отдельным workflow, с обязательным cleanup; итоговый run добавляется после завершения. Production Supabase не изменялся.
