# Единые пустые состояния CRM — 2026-07-15

Связано: #96 и #200.

## Проблема

Заявки, связанные заказы, финансовый контроль и аудит публичных заявок используют одинаковый блок `.v4-empty` для разных ситуаций:

- данные загружаются;
- запрос завершился ошибкой;
- раздел ещё не запускался;
- в базе действительно нет записей;
- текущий фильтр ничего не нашёл;
- в финансовой группе нет рисковых заказов.

Одинаковая серая строка не объясняет сотруднику, что произошло и какое действие безопасно выполнить дальше.

## Решение

Добавлен read-only sidecar:

- `crm-empty-state-model-v1.js` — чистая модель контекста и состояния;
- `crm-empty-state-enhancer-v1.js` — DOM-enhancer;
- `crm-empty-state-v1.css` — единый визуальный компонент.

Sidecar подключается одной side-effect import строкой из `crm-v4-tabs-lite.js` и наблюдает только четыре известных контейнера:

- `#leadsList`;
- `#ordersBox`;
- `#financeControlContent`;
- `#publicLeadAuditContent`.

Другие `.v4-empty` не меняются.

## Поведение

### Заявки

- загрузка: объясняет, что получаются последние обращения;
- ошибка: показывает безопасное объяснение и кнопку `Обновить заявки`;
- раздел ещё не загружен: предлагает запустить загрузку;
- база пуста: объясняет, где появятся новые обращения;
- фильтр пуст: сохраняет кнопку `Сбросить фильтры`.

### Заказы

- загрузка: поясняет проверку связей заявки, расчёта и КП;
- ошибка: подчёркивает, что существующие связи не менялись;
- карточка не выбрана: объясняет, где появятся заказы;
- заказ ещё не создан: объясняет следующий шаг через согласованное КП;
- повторное создание или отсутствие согласованного КП отображается как заблокированный следующий шаг, а не как техническая ошибка.

### Финансы

- загрузка и начальное состояние получают понятные инструкции;
- при ошибке сообщается, что заказы и оплаты не менялись;
- пустая рисковая группа показывается зелёным компактным состоянием: отсутствие заказов с таким риском — положительный результат;
- кнопка `Обновить финансы` использует уже существующий обработчик.

### Аудит заявок

- загрузка, ошибка и начальное состояние имеют явные действия;
- пустой поиск или фильтр получает кнопку `Очистить фильтр`;
- очистка использует существующие input/filter handlers;
- журнал и публичные заявки enhancer не изменяет.

## Безопасность и границы

Enhancer:

- не импортирует Supabase client;
- не выполняет SELECT, INSERT, UPDATE, DELETE, UPSERT или RPC;
- не меняет state объектов CRM;
- не меняет бизнес-статусы;
- не создаёт новые данные;
- сохраняет существующие action buttons и их `data-*` attributes;
- добавляет только заранее определённые действия, которые уже обрабатываются текущими модулями;
- использует `textContent`, а не вставляет динамические ошибки через HTML;
- работает через `MutationObserver`, поэтому повторно применяет оформление после штатного rerender;
- помечает обработанный узел `data-v4-empty-state-enhanced="1"`, предотвращая цикл observer.

Supabase production и staging не меняются.

## Доступность

- loading/empty состояния используют `role="status"` и `aria-live="polite"`;
- error использует `role="alert"` и `aria-live="assertive"`;
- иконка декоративная и скрыта от screen reader;
- анимация отключается при `prefers-reduced-motion: reduce`;
- на мобильном действия становятся полноширинными.

## Проверки

`test_crm_empty_state_model.mjs` проверяет:

- четыре разрешённых контекста;
- классификацию loading/error/initial/filtered/empty;
- позитивное состояние пустой финансовой группы;
- корректные action attributes;
- отказ для неизвестного контейнера.

`check_crm_empty_states.py` проверяет:

- точечное подключение sidecar;
- ограниченный список контейнеров;
- отсутствие Supabase/write markers;
- доступность и reduced-motion;
- сохранение существующих action attributes;
- связь документа, теста и workflow.

## Ручная проверка

1. Открыть CRM и раздел `Заявки`.
2. Проверить loading и загруженный список.
3. Ввести поиск без совпадений: должно появиться объяснение и `Сбросить фильтры`.
4. Открыть карточку заявки без заказа: пустое состояние должно объяснить следующий шаг.
5. Открыть `Финансы`: пустые группы рисков должны отображаться зелёными компактными блоками.
6. Открыть `Аудит заявок`, задать поиск без совпадений и нажать `Очистить фильтр`.
7. На ширине до 560 px проверить полноширинные кнопки.
8. Убедиться, что реальные карточки заявок, заказов и аудита enhancer не изменяет.
