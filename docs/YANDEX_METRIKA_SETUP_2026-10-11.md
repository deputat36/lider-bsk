## Что настроено в коде

Общая форма v36 на всех 64 публичных страницах сохраняет текущую отправку заявок
в CRM, удержание меток кампании и стабильный номер при повторе. Backend и рабочие
заявки не изменяются. Проверки выполняются на локальных фикстурах без передачи
тестовых обращений в production.

| Событие | Когда отправляется | Назначение |
| --- | --- | --- |
| `lead_confirmed` | Ответ сервера `ok:true`, первый показ подтверждения данного номера в текущей сессии | Основная цель принятого обращения через форму |
| `lead_sent` | Первое подтверждение и `duplicate` не равен true | Новая запись; не суммировать с `lead_confirmed` |
| `lead_duplicate` | Сервер сообщил, что запись уже существует | Диагностика повторов, не новая заявка |
| `phone_click` | Нажатие ссылки `tel:` | Намерение позвонить; не подтверждение фактического разговора |
| `messenger_click` | Прямая ссылка в мессенджер; для обычного VK-профиля нужен явный признак контактной ссылки | Намерение написать; не факт отправки сообщения |
| `email_click` | Нажатие `mailto:` | Намерение написать письмо |
| `community_click` | Переход в публичное сообщество VK | Просмотр площадки, отдельно от обращения |
| `form_view` | Видно не менее 10% формы; один раз на страницу | Шаг воронки; при отсутствии IntersectionObserver используется проверка видимости при прокрутке |
| `form_start` | Первое изменение полей формы | Шаг воронки |
| `form_submit_attempt` | Валидная форма начинает отправку | Попытка; не успешная заявка |
| `lead_send_error` | Ответ неуспешен или сеть не ответила | Диагностика |
| `service_select` | Выбор услуги в форме или кнопкой | Интерес к услуге |
| `service_page_click` | Переход на определённую услугу общего каталога | Навигация по услугам |
| `contact_method_select` | Выбор способа ответа | Предпочтительный канал без контактного значения |

В параметрах пользовательских целей передаются путь страницы, известные ID
услуги и направления, тип канала, место ссылки и допустимые диагностические
признаки. Имя, телефон, сообщение, email, VK-профиль, полный URL, текст ссылки
и номер обращения в `reachGoal` не передаются. Локальное событие `leader:goal`
сохраняет совместимость с помощниками сайта; оно не является передачей в Метрику.

Вебвизор остаётся включён. Для полей, включая динамический бриф, используется
`ym-disable-keys`; для формы — `ym-disable-submit`; для номера подтверждения —
`ym-hide-content`. Эти классы документированы Яндексом. Пользовательские цели
передаются явно и не зависят от автоматического учёта отправки формы.

Если первый ответ сервера потерян, а повтор возвращает существующую запись,
первое видимое подтверждение всё равно достигает `lead_confirmed`. Второе
подтверждение того же номера в этой сессии не создаёт вторую конверсию.
Память подтверждений ограничена 50 последними номерами текущей сессии.
Нажатие телефона, изменение полей и ошибка сети не достигают эту цель.
Ответ `ok:true` на заполненную антиспам-ловушку также не учитывается: backend
подтверждает такой запрос без создания заявки. Это проверено отдельной фикстурой.

## Почему кабинет ещё не настроен

При открытии https://metrika.yandex.ru/ отображалась страница «Метрика пока
недоступна» с сообщением о восстановлении сервисов Яндекса. Настройки счётчика
и цели недоступны. Объявление Яндекса обновлено 11 октября 2026 года:
[состояние восстановления](https://yandex.ru/company/news/09-10-2026-01).

Не проверены: принадлежность счётчика, список существующих целей, сохранение
новых целей, домены и фильтры, отчёты по конверсиям, связь с Вебмастером.
Источник события в коде и цель в кабинете — разные части настройки.

## Завершение после восстановления доступа

1. Открыть существующий счётчик 109387236 и подтвердить, что он относится к сайту.
   Использовать безопасный вход владельца, если его потребует сервис; пароль
   в переписке не нужен.
2. Проверить имеющиеся цели. Существующие подходящие цели использовать повторно;
   другие настройки и историю не удалять.
3. Создать отсутствующие цели типа «Целевое событие» с точными идентификаторами.
   Основные: `lead_confirmed`, `phone_click`, `messenger_click`, `email_click`.
   Шаги воронки: `form_view`, `form_start`, `form_submit_attempt`. Диагностику
   рассматривать отдельно. Legacy `mobile_*` не суммировать с каноническими кликами.
4. Проверить домен, HTTPS, настройки сессий и необходимые фильтры по фактической
   конфигурации. Не объявлять все переходы в публичные VK-сообщества обращениями.
5. Проверить загрузку счётчика и один безопасный клик. Для успешной заявки
   использовать естественное реальное обращение или согласованную отдельную
   проверку; тестовую запись в рабочую CRM автоматически не создавать.
6. Подтвердить сохранённые цели и поступление данных в кабинете. До этого не
   считать настройку аккаунта и достоверность отчётов завершёнными.
