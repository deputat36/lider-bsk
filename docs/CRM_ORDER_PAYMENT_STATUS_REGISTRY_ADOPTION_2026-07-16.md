# CRM v4: единые статусы оплаты в контроле заказов

Дата: 2026-07-16

Связано: #200, #217, PR source-only.

## Цель

Использовать один canonical registry статусов оплаты во всех read-only очередях, где CRM решает, закрыта ли оплата заказа и нужен ли контроль.

## Затронутые представления

- фильтр `Оплата под контролем` в общем списке заказов;
- раздел `Контроль заказов`;
- менеджерская очередь внимания;
- существующий `Финансовый контроль` остаётся эталонной реализацией.

## Canonical поведение

| Значение | Registry key | Контроль оплаты |
|---|---|---|
| `Не оплачено` | `unpaid` | да |
| `Предоплата` | `prepayment` | да |
| `Частично оплачено` | `partial` | да |
| `Оплачено` | `paid` | нет |
| неизвестная строка | неизвестно | да, с предупреждением |
| пустое значение | `unpaid` через безопасный fallback | да |

Неизвестное значение не переписывается и не считается оплаченной суммой. Оно остаётся видимым до явного сопоставления с registry.

## Изменения

### `order-list-preferences-v1.js`

- удалена эвристика по подстрокам `не`, `част`, `долг`, `ожид`;
- фильтр использует `paymentNeedsAttention()` из `payment-status-ui-model-v1.js`;
- поиск дополнительно учитывает canonical label оплаты;
- настройки фильтра по-прежнему хранят только `filter` и `sort`, без поисковой строки и персональных данных.

### `order-control-v2.js`

- очередь оплаты и счётчик используют canonical registry;
- карточка показывает canonical label и registry key в подсказке;
- неизвестный статус получает `data-unknown-payment-status` и отдельное предупреждение;
- добавлен счётчик `Неизвестный статус оплаты`.

### `management-attention-model-v1.js`

- менеджерская очередь больше не определяет задолженность по подстрокам;
- `Оплачено` не создаёт финансовую задачу;
- предоплата, частичная оплата, неоплата и неизвестные значения создают задачу `Оплата не закрыта`;
- fallback из `order.data.payment_status` и `order.data.paymentStatus` сохранён.

## Manual browser check

1. Открыть список заказов и выбрать `Оплата под контролем`.
2. Убедиться, что `Не оплачено`, `Предоплата` и `Частично оплачено` остаются в списке.
3. Убедиться, что `Оплачено` исключено из очереди оплаты.
4. Временно проверить fixture с `Оплата на проверке банка`: строка должна остаться в контроле и показать предупреждение `Неизвестный статус оплаты`.
5. Открыть `Контроль заказов` и убедиться, что счётчики совпадают с общим списком.
6. Проверить менеджерскую очередь внимания: полностью оплаченный заказ без других рисков не должен создавать задачу по оплате.
7. В Network убедиться, что пакет не добавляет POST, PATCH, INSERT, UPDATE, DELETE или RPC.
