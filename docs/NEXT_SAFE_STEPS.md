## Browser E2E — граница разрешения

Browser E2E создаёт реальную строку в `leader_leads` и audit-событие в production. Поэтому его выполнять только после отдельного явного разрешения владельца.

После разрешения:

1. Использовать URL и UTM из `docs/PUBLIC_REQUEST_BROWSER_E2E_RUNBOOK_2026-07-12.md`.
2. Отправить одну явно помеченную техническую заявку с контролируемым номером телефона.
3. Записать возвращённый `request_id`.
4. Проверить Network response: HTTP 200, `ok=true`, тот же `request_id`.
5. Выполнить только read-only SQL из runbook.
6. Подтвердить одну заявку и audit `accepted / lead_insert_created`.
7. Duplicate, suspicious и rejected проверять только как отдельные согласованные сценарии.
8. Не публиковать телефон и другие персональные данные в GitHub issue или отчёте.

## Supabase production

Supabase production не менять без отдельного согласования владельца:

- не выполнять DDL/DML;
- не применять migrations;
- не менять RLS, grants, policies, Auth или Storage;
- не deploy-ить Edge Functions;
- не удалять и не исправлять реальные заявки;
- не создавать Supabase development branch без подтверждения стоимости.

Разрешены read-only metadata, SELECT, логи и advisors, если они нужны для проверки текущего состояния.
