# Постоянная подпись Android APK: «Этажи • СМС Визитка»

Начиная с **Release v0.6.1 (versionCode 10)** приложение имеет постоянную подпись. Предыдущие Debug APK удаляются перед первой установкой этой release-версии. Все дальнейшие APK с большей `versionCode` и тем же сертификатом устанавливаются поверх Release с сохранением данных Android.

## Зафиксированный сертификат

- Alias: `smsvizitka`
- Тип хранилища: PKCS12
- SHA-256: `30F7402FD12EC280E1D5F4A5C945109836537A0830D317FD766C23C511DDEAA3`
- Срок действия: до 05.10.2126

**Секретный ключ и его пароль в репозитории не хранятся.** Резервную копию выдавать только владельцу приложения; хранить автономно минимум в двух защищённых местах. Потеря ключа/пароля может сделать обновления без переустановки невозможными.

## Один раз подключить GitHub Actions

В `deputat36/lider-bsk` → Settings → Secrets and variables → Actions добавить четыре Repository secrets:

| Secret | Значение |
|---|---|
| `SMS_SIGNING_KEYSTORE_B64` | Base64 содержимого файла `SMS-Vizitka-release-keystore.p12` |
| `SMS_SIGNING_STORE_PASSWORD` | пароль оригинального PKCS12 |
| `SMS_SIGNING_KEY_PASSWORD` | тот же пароль |
| `SMS_SIGNING_ALIAS` | `smsvizitka` |

Для Windows предусмотрен подготовленный скрипт `setup-sms-vizitka-signing.ps1` (предоставляется владельцу): нужен установленный GitHub CLI (`gh auth login`) и сохранённые рядом исходный `.p12` + пароль. Скрипт устанавливает все четыре секрета через шифруемое подключение к GitHub.

Общий workflow `.github/workflows/sms-vizitka-build.yml` уже выполняет условную release-подпись. При отсутствии секретов сборка успешно создаёт только Debug и unsigned Release. При наличии секретов выдаёт отдельный `*-release-signed` artifact, автоматически проверяет цифровую подпись и **отказывается выпускать APK с чужим сертификатом**.

## Для будущих версий

1. Увеличить `versionCode` (после v0.6.1 — минимум 11) и `versionName`.
2. Создать и проверить сборку на GitHub Actions.
3. Установить **только** `release-signed` поверх предыдущей подписанной Release.
4. Никогда не отправлять сотрудникам Debug вместо подписанного APK — у Debug другая подпись.
5. Не генерировать новый ключ для каждого выпуска.

Штатное Android Backup отключено. При переходе с Debug на стабильную Release необходимые данные надо предварительно сохранить отдельно: обычный экспорт приложения не включает историю и стоп-лист.

Условия установки поверх старой версии: тот же applicationId, та же подпись и более высокая `versionCode`.
