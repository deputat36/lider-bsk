# Этажи • СМС Визитка — Android v0.6.0

Версия 0.6.0 (versionCode 9), Android 10+ (minSdk 29). Приложение не отправляет SMS скрытно: каждое сообщение открывается в стандартном SMS-клиенте.

## Изменения
- Кампании, получатели, история подготовленных SMS, реестр повторов, стоп-лист и диагностика перенесены в SQLite через штатный SQLiteOpenHelper.
- При первом запуске осуществляется транзакционный импорт из файлов v0.5.2 (`bulk_campaign_active.json`, `bulk_campaign_history.json`, `recipient_policy.json`) и истории из `sms_card_history` SharedPreferences.
- Миграция атомарная и повторяемая: флаг ставится только после успешного переноса; исходные JSON и SharedPreferences не удаляются.
- Для изменения одного получателя обновляется только изменившаяся строка `campaign_recipients`.
- Создание новой большой кампании перенесено с UI-потока; двойная активная кампания запрещена.
- Нижняя навигация вместо тесных вкладок над контентом.
- Диагностика событий в настройках: предложение после звонка, открытие SMS-клиента, проблемы с вызовами. Не записывает сами номера или содержимое SMS.
- При неоднозначном наложении вызовов приложение не показывает предложение, чтобы не предложить отправить SMS не тому клиенту.
- Прежние ограничения: защита от повторов, стоп-лист, фильтры телефонной книги и ручное подтверждение SMS.
- Unit-тесты очереди дополнили существующие тесты номеров и срока жизни сессии.

## Миграция и сохранность
При обновлении с v0.5.2 с тем же сертификатом подписи данные приложения сохраняются и перенос выполняется один раз. Старые файлы сохраняются на устройстве; после успешной миграции приложение читает SQLite. Если миграция не удалась, запуск хранилища блокируется без удаления исходных данных. Экспорт JSON по-прежнему переносит профиль и шаблоны, но не клиентские кампании.

Для замены debug APK постоянной release-подписью Android может потребовать удалить старую версию. До удаления обязательно экспортируйте настройки. Активная кампания и стоп-лист в текущий файл экспорта не входят; их перенос через удаление приложения не гарантирован. Поэтому для пользователей с активными кампаниями замену debug на release пока не делать.

## Подпись
Release по умолчанию unsigned. В GitHub Actions предусмотрена условная подпись при наличии четырёх секретов:
- `SMS_SIGNING_KEYSTORE_B64`: Base64 байтов постоянного JKS/PKCS12 keystore
- `SMS_SIGNING_STORE_PASSWORD`
- `SMS_SIGNING_KEY_PASSWORD`
- `SMS_SIGNING_ALIAS`

Файл keystore и пароли нельзя хранить в GitHub-репозитории или общих чатах. Если секреты ещё не настроены, готовый устанавливаемый вариант — debug APK (только для тестирования).

## Что остаётся проверить
- Фактический перенос данных с v0.5.2 на реальных телефонах (в том числе кампаний в процессе)
- Dual SIM/call waiting у разных производителей: безопасный пропуск при неоднозначности реализован, но точное определение каждого параллельного звонка не гарантировано
- Настройки баннеров и фоновых ограничений на Samsung/Xiaomi/vivo/OPPO/Honor
- Подпись release и обновление без переустановки после того, как пользователь безопасно настроит постоянный ключ
- Учёт документального согласия на рекламные рассылки (пока только предупреждение, приложение не является системой доказательства согласия)

## Сборка
CI: Java 17, Gradle 9.6, AGP 9.4, SDK 37. Выполняются JUnit, Android Lint, debug/release build. Исходный ZIP формируется из ровно того исходного каталога, что использован для APK.

Все данные локальные. Android Backup выключен.
